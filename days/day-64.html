Production Runtime

Day 64 — Background Agent Architecture

Background agent architecture treats long work as durable jobs rather than long HTTP requests. The user can leave while the system owns progress and completion.

Simple example

An agent researches 500 contracts over two hours; workers restart during the run, but the job keeps its state and later notifies the user.

Trade-offs

  • Async jobs improve resilience but complicate UX.
  • Long work can outlive credentials and assumptions.
  • Cancellation and partial results need explicit semantics.

Production readiness checks

  • Return a durable job ID.
  • Use leases and heartbeats.
  • Persist progress/checkpoints.
  • Revalidate permissions and external state before sensitive steps.
