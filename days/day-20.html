Day 20 — Agent Rollback

Rollback is how you reverse a change made by an agent when the result is wrong. Not every action is reversible, so design compensation before autonomy.

Simple example

An agent updates a configuration; rollback stores the previous version and can restore it quickly.

Trade-offs

  • Rollback works well for reversible state changes.
  • External side effects may require compensation instead.
  • Rollback data adds storage and implementation cost.

Production readiness checks

  • Classify reversible vs irreversible actions.
  • Store previous state or inverse operations.
  • Test rollback paths regularly.
  • Require stronger approval when rollback is impossible.
