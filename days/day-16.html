Safety and Security

Day 16 — Secrets and PII Protection

Secrets and PII should not become normal prompt content. Minimize what enters the model and redact or tokenize sensitive fields when possible.

Simple example

A troubleshooting agent can know that authentication failed without receiving the user's full access token.

Trade-offs

  • Redaction can remove context needed for debugging.
  • External model providers change data-handling requirements.
  • Logs can leak secrets even when prompts are protected.

Production readiness checks

  • Classify sensitive fields.
  • Mask secrets before prompts and logs.
  • Set retention rules.
  • Test prompts, traces and tool outputs for accidental leakage.
