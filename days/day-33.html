Tool and API Architecture

Day 33 — REST for Agents

REST is a strong default for request/response tools. Agents benefit from its simple contracts, but long work should not be forced into a single blocking call.

Simple example

The agent calls GET /orders/123, then POST /refunds with a validated payload.

Trade-offs

  • Easy to integrate and observe.
  • Polling long jobs wastes calls.
  • Retries of POST requests can duplicate effects without idempotency.

Production readiness checks

  • Use timeouts and idempotency keys.
  • Return stable error bodies.
  • Prefer async job APIs for long operations.
  • Propagate correlation IDs.
