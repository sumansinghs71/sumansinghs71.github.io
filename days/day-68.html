Day 68 — Context Rot

More context can make an agent worse when stale, duplicate, irrelevant or conflicting information buries the signal it actually needs.

Key idea

The goal is not to lose information. The goal is to stop treating every available piece of information as equally worthy of the model's attention.

Simple example

An incident agent receives today's alert, an old runbook, three duplicated chat summaries, last month's incident notes and a stale memory saying the service still runs on the previous deployment. The correct evidence is present, but it competes with louder or repeated information and the agent chooses the wrong tool path.

Trade-offs

  • Aggressive pruning can hide rare but important history.
  • Ranking, deduplication and freshness checks add latency and system complexity.
  • Freshness is domain-specific: old information can be obsolete in one workflow and essential evidence in another.

Production readiness checks

  • Rank context by relevance and freshness before prompting.
  • Deduplicate repeated chunks, messages and memories.
  • Detect conflicting facts instead of silently mixing them.
  • Expire stale working memory, but keep durable sources available for retrieval.
  • Trace which context items reached the model and evaluate quality as context grows.
