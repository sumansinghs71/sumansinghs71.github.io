Day 06 — Tool Basics

Tools are the controlled capabilities an agent can call. A good tool hides system complexity and exposes one clear contract.

Simple example

Instead of giving SQL access, expose `get_customer_balance(customer_id)` with authorization and validation built in.

Trade-offs

  • Small tools are safer but may require more calls.
  • Very broad tools reduce calls but expand blast radius.
  • Poor descriptions cause wrong tool selection.

Production readiness checks

  • Use typed inputs and outputs.
  • Validate parameters outside the model.
  • Apply authorization inside the tool.
  • Log side effects and return stable error codes.
