Day 43 — State Machines

A state machine makes allowed transitions explicit. It is useful whenever an agent task has meaningful lifecycle states.

Simple example

A deployment request moves DRAFT → VALIDATED → APPROVED → EXECUTING → DONE, with no direct jump from DRAFT to EXECUTING.

Trade-offs

  • Explicit states improve auditability.
  • Too many states can become hard to maintain.
  • Flexible tasks may not fit a rigid machine.

Production readiness checks

  • Define valid transitions.
  • Make transitions atomic.
  • Store transition reasons and actors.
  • Test illegal transition attempts.
