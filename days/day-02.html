Day 02 — Agent Blast Radius Design

Blast radius is the maximum damage an agent can cause when it is wrong. Design that boundary before improving the model.

Simple example

A billing agent may read every invoice but can only refund up to $100 without approval.

Trade-offs

  • Tighter limits reduce risk but can add friction.
  • Broad permissions make demos easy and incidents expensive.
  • A single global limit is often too coarse; risk changes by action.

Production readiness checks

  • List irreversible actions.
  • Set limits per tool and per user.
  • Require approval above risk thresholds.
  • Test the boundary with deliberately bad requests.
