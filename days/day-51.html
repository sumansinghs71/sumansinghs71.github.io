Day 51 — Orchestration Anti-Patterns

Orchestration anti-patterns are designs that look flexible but hide control: giant prompts as workflows, unbounded loops, shared mutable state, and retries without semantics.

Simple example

A single agent prompt contains 40 steps, 30 tools and every exception path; no one can tell which rule executed.

Trade-offs

  • Less structure is fast to prototype.
  • More orchestration code costs engineering time.
  • The right boundary depends on task risk and variability.

Production readiness checks

  • Make critical state explicit.
  • Bound loops and retries.
  • Use small tool contracts.
  • Prefer observable workflow transitions over hidden prompt logic.
