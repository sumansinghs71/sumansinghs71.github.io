Day 67 — Agent Workspaces

Context is for reasoning. Workspaces hold the files, durable state and artifacts an agent needs to continue real work without stuffing everything back into the prompt.

Key idea

The context window should be a small working set, not the system of record. Keep durable information outside the prompt and pull it back only when the next step needs it.

Simple example

A coding or research agent may work for hours. Instead of replaying every file, log and intermediate result into the model on each step, it keeps source files and scratch work in a filesystem, workflow state in a durable store, and generated reports or charts as versioned artifacts. The model receives only the working set it needs for the next decision.

Trade-offs

  • A real workspace adds state-management and cleanup complexity.
  • Files, database state and artifacts can drift unless versions are tied to the same run.
  • Shared workspaces are dangerous unless tenant, user and task boundaries are explicit.

Production readiness checks

  • Isolate the workspace per run, user or tenant.
  • Version artifacts and checkpoint durable workflow state.
  • Enforce TTLs, storage quotas and cleanup for abandoned work.
  • Apply the same authorization boundary to files, state and artifacts.
  • Prove a fresh worker can reopen the workspace and continue safely.
