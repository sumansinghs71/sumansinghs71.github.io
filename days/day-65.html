Day 65 — Checkpoint, Resume & Replay

Checkpoint, resume and replay recover long-running work without starting from zero. A checkpoint is useful only if replay will not repeat side effects.

Simple example

A 10,000-record agent crashes after 7,200. It resumes from saved progress, verifies the last external action, and continues safely.

Trade-offs

  • Frequent checkpoints improve recovery but add storage/write overhead.
  • Sparse checkpoints waste more work after failure.
  • External state can change while the agent is down.

Production readiness checks

  • Checkpoint durable state and version it.
  • Record action receipts for side effects.
  • Revalidate external state after resume.
  • Test crashes before and after each irreversible action.
