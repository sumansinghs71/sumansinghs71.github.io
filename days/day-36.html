Day 36 — SSE and WebSockets

SSE and WebSockets keep a connection open for streaming. SSE is simpler for server-to-client updates; WebSockets support two-way real-time messaging.

Simple example

An agent streams progress with SSE while a collaborative control UI uses WebSockets for two-way commands.

Trade-offs

  • Long connections need load-balancer support.
  • WebSockets add connection state.
  • Streaming partial output complicates moderation and recovery.

Production readiness checks

  • Support reconnect and resume tokens.
  • Set idle timeouts deliberately.
  • Do not treat connection close as task completion.
  • Observe active connections and backpressure.
