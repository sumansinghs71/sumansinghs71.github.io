Day 07 — When NOT to Use Agents

Do not use an agent when rules are stable, inputs are structured, and the correct path is known. Autonomy adds cost and uncertainty.

Simple example

A nightly file rename job should be a script, not an agent deciding what to do every night.

Trade-offs

  • Deterministic automation is cheaper and easier to prove correct.
  • Agents help when ambiguity or changing context matters.
  • Hybrid designs can keep deterministic cores with agentic edges.

Production readiness checks

  • Compare against a workflow baseline.
  • Measure cost per successful task.
  • Identify where judgment is actually required.
  • Keep a non-agent fallback for critical paths.
