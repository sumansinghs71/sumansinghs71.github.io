Day 58 — Safety Evals

Safety evals probe whether the system stays within boundaries under adversarial or risky conditions while remaining useful on normal requests.

Simple example

A tool-enabled agent is tested on direct jailbreaks, malicious documents and ambiguous requests that should still be answered safely.

Trade-offs

  • Aggressive refusal can hurt usefulness.
  • Adversarial coverage is never complete.
  • Model safety does not replace runtime permissions.

Production readiness checks

  • Test direct and indirect attacks.
  • Measure false refusals.
  • Include tool and data boundaries.
  • Repeat safety suites after model/tool changes.
