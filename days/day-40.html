Tool and API Architecture

Day 40 — SOAP and Legacy Systems

SOAP is common in legacy enterprise systems. Agents should not reason over raw XML contracts; adapters should present stable, validated tools.

Simple example

A modern agent calls `get_policy_status()` while an adapter handles WSDL, namespaces and SOAP faults.

Trade-offs

  • Adapters reduce model complexity but add maintenance.
  • Legacy services may have strict schemas and slow responses.
  • Fault handling is more complex than plain HTTP status codes.

Production readiness checks

  • Generate clients from approved WSDLs.
  • Map SOAP faults to stable tool errors.
  • Set strict timeouts.
  • Test schema changes with contract tests.
