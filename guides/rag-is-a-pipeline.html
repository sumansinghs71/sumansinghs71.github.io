Teaching thread · RAG & Knowledge

RAG is a pipeline, not a vector database

When a RAG answer is wrong, blaming the model is often the fastest way to waste a day. The answer is the last step in a chain, and each earlier step can remove or distort the evidence before the model ever sees it.

30-second idea: The final answer can fail because of ingestion, chunking, metadata, retrieval, reranking, freshness or grounding.

Ask what evidence reached the model

A good debugging trace should let you follow a source from ingestion to chunking, indexing, filtering, retrieval, reranking and final context. If the right document disappeared at metadata filtering, changing the prompt cannot fix it.

Final-answer quality can hide retrieval failure

Strong models can answer from prior knowledge or infer around weak context. That feels helpful until the domain changes and prior knowledge is stale. Retrieval-specific evals matter because they catch problems the final-answer score can hide.

Freshness has multiple clocks

The source can be updated while ingestion, embeddings, replicas or caches are still old. A single 'last sync succeeded' metric is not enough. What matters is the age and version of the evidence that actually reached the model.

Evaluate claims against sources

A citation is not automatically grounding. The cited source must support the specific claim. In production, citation correctness, source trust and retrieval recall belong beside answer quality—not underneath it.

The production pattern

Trace source IDs end to end
Measure recall@k and reranker contribution
Slice by filters and document type
Track source-to-context freshness
Check citation support
