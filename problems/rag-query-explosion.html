Knowledge & RAG

⌘ A retrieval feature turned one query into thousands of clauses

Hybrid retrieval can fail before ranking begins when query expansion exceeds the search engine’s operational limits.

What it looks like

  • Only some filtered or hybrid searches fail.
  • Queries become dramatically larger after a feature flag or metadata expansion.
  • The model never receives evidence because the retrieval engine rejects the query.

Why this happens

RAG has hard infrastructure limits: Boolean clauses, filter cardinality, request size, top-k, fan-out and latency budgets. Query rewriting or hybrid expansion can multiply terms until a legal logical query becomes an illegal physical request.

A simple real-world example

A retrieval pipeline expands user intent into lexical terms, vector candidates and a large metadata allow-list. A new hybrid mode combines them into one request and crosses the engine’s maximum-clause limit.

What teams usually get wrong

  • Treating query expansion as free.
  • Catching the search error and blaming the model.
  • Removing filters without considering security/tenant boundaries.
  • Enabling hybrid features globally without cardinality tests.

What I would put in production

  • Set explicit budgets for clauses, filters, candidates and request size.
  • Measure expansion before executing the search.
  • Degrade safely: simplify optional expansions while preserving authorization filters.
  • Test worst-case metadata cardinality.
  • Keep feature flags reversible and observable.

What I would monitor

query clause count
filter cardinality
search rejection rate
retrieval latency by query shape
Takeaway: RAG correctness starts before retrieval: the query itself has to fit inside the engine.
