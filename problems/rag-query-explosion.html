Knowledge & RAG

Σ One RAG feature flag turned a query into thousands of clauses.

Hybrid retrieval and query expansion can exceed engine limits even when the user's question is small.

What it looks like

  • Search fails with a maximum-clause or query-complexity error.
  • The failure appears only for certain filters, expansions or feature flags.
  • Removing one retrieval mode immediately restores service.

The failure boundary

The user query is small, but the generated search plan is not. Complexity is created between orchestration and the search engine.

Why this happens

Hybrid retrieval may combine rewritten queries, metadata filters, synonym expansion, lexical clauses, vector searches and tenant restrictions. Each layer can multiply the final query. Search engines have hard limits, so query shape must be treated as a budgeted resource.

A production-shaped example

A retrieval feature enables multiple rewrites and expands metadata conditions for a large entitlement set. The final search request contains several thousand Boolean clauses and the engine rejects it before retrieval begins.

What fooled the team

  • Looking only at user-query length.
  • Increasing engine limits instead of bounding query construction.
  • Enabling hybrid retrieval globally without slice testing.
  • Logging the original question but not the final generated search plan.

Prevent

  • Define a query-complexity budget before sending work to the search engine.
  • Cap rewrites, filter expansions, synonyms and Boolean clause count.
  • Use set-based/lookup filters where supported instead of giant OR lists.
  • Provide a simpler retrieval fallback when the planned query exceeds budget.

Detect

  • Log clause count, rewrite count, filter cardinality and final serialized query size.
  • Slice failures by retrieval mode, tenant and feature flag.
  • Alert before hard engine limits are reached.

Recover

  • Retry with a bounded fallback query, not the identical oversized request.
  • Disable the offending expansion path through a safe feature switch.
  • Preserve the failed query plan for debugging and regression tests.

Prove it with failure injection

  • Large entitlement/filter sets.
  • Worst-case synonym and rewrite expansion.
  • Hybrid search with maximum metadata cardinality.
  • Fallback behavior when the query budget is exceeded.

What I would monitor

final clause count
filter cardinality
query-plan size
search hard-limit errors
fallback retrieval rate

Production invariant

No generated retrieval plan reaches the search engine without passing a bounded complexity check.
Takeaway: RAG can fail before retrieval. Measure the query you actually send, not only the question the user typed.
