Production problem

↻ The agent executed the same action twice

The first action may have succeeded, but the agent retried because it never received or persisted the result.

What it looks like

  • A customer is charged twice.
  • The same email or ticket update appears twice.
  • The logs show a timeout followed by a retry, but not whether the first call succeeded.

Why this happens

This usually starts as a normal reliability feature: retry when a network call fails. The problem is that a timeout does not mean the remote system failed. It only means your system did not receive a response in time. The provider may already have completed the action. If the worker crashes before saving that fact, a later retry can perform the side effect again.

A simple real-world example

Imagine a payment agent sends a $75 refund. The payment provider applies it, but the connection drops before the response reaches your runtime. Your agent records 'tool failed' and retries. Without an idempotency key or action receipt, the provider sees a second legitimate refund request. From the model's point of view it retried a failed call. From the customer's point of view they were refunded twice.

What teams usually get wrong

  • Treating every timeout as proof that nothing happened.
  • Adding generic retries around write tools without defining retry semantics.
  • Relying on the LLM to remember what it already did.
  • Calling a workflow 'exactly once' without naming the actual guarantee and failure boundary.

What I would put in production

  • Use a stable idempotency key for each logical action, not each network attempt.
  • Persist action receipts: requested, accepted, completed, provider reference.
  • On resume, reconcile uncertain actions before retrying them.
  • Separate retryable reads from high-impact writes.
  • Test the ugly crash point: remote action succeeded, local commit did not.

What I would monitor

duplicate action rate
unknown/ambiguous action states
provider reconciliation mismatches
retries by tool and error class
