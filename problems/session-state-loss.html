State & RoutingProduction failure pattern

↔The next message hit another worker—and the conversation disappeared.

Session affinity can hide a state-design bug until autoscaling, failover or cross-zone routing moves the next turn.

turn 1→worker A + memory→turn 2→worker B: empty
Routing moved; the state did not.
Signals in production
  • Follow-up questions look like brand-new conversations.
  • The bug is intermittent and worse after scaling or failover.
  • Single-node tests pass; multi-replica production fails.
Failure boundary

Correctness depends on process-local state that is not reconstructable on another healthy worker.

01

Why it happens

Sticky sessions improve locality, but they are not durable state. Workers restart and requests move. Conversation history, sequence/version and workflow control state need a shared source of truth when continuity matters.

02

Production-shaped example

Turn one lands on worker A and stores context only in memory. Turn two lands on worker B after a routing change. The request is valid, but the model lacks the prior state needed to interpret it.

What fooled the team
using stickiness as persistenceconversation ID without version/state guaranteestesting on one replica
First 5 minutes
  1. Compare routing target across adjacent turns.
  2. Inspect conversation version/sequence and where state was loaded from.
  3. Force a durable reload and check for stale/out-of-order writes.
03

Controls

Prevent the failure, detect it early, then recover without making it worse.

PREVENT
  • Persist canonical conversation/workflow state outside the worker.
  • Use affinity only as a locality optimization.
  • Carry stable conversation ID plus monotonic sequence/version.
  • Use optimistic concurrency or equivalent protection against stale overwrites.
DETECT
  • Log worker/region, state source and version for every turn.
  • Alert on context misses, sequence gaps and unexpected session resets.
  • Trace cross-worker state reconstruction latency.
RECOVER
  • Reload latest durable state on routing miss.
  • Reject or reconcile stale/out-of-order updates.
  • Rebuild transient caches from durable history.
Prove it with failure injection
  • alternate worker every turn
  • restart worker between turns
  • duplicate/out-of-order messages
  • cross-region failover mid-session
Monitor

PRODUCTION INVARIANTAny healthy worker receiving a valid conversation ID can reconstruct the state needed to continue correctly.

Affinity may improve locality. Correctness should not depend on one process staying alive.
