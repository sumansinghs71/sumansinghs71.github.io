Knowledge & RAG

🧠 The agent remembered something that is no longer true

Persistent memory can make an agent more useful, but it can also preserve outdated assumptions for months.

What it looks like

  • The same incorrect preference or fact keeps reappearing across sessions.
  • New source data disagrees with old memory, but the memory still wins.
  • Users cannot tell where a remembered claim came from or how to correct it.

Why this happens

Memory changes the failure mode from 'the model forgot' to 'the system remembered the wrong thing.' Facts expire, user preferences change and previous agent conclusions can be wrong. If every successful interaction is promoted into memory with no provenance, confidence or TTL, a temporary mistake can become a durable instruction.

A simple real-world example

An operations agent learns that a vendor's cutoff is 5 PM and stores it as memory. The vendor later changes the cutoff to 3 PM, and the source documentation is updated. The agent keeps scheduling transfers at 4 PM because its old memory is injected before retrieval. Nothing crashes; the agent is simply confidently outdated.

What teams usually get wrong

  • Treating all memories as equally trustworthy.
  • Never expiring or revalidating operational facts.
  • Letting model-generated summaries overwrite source-backed facts.
  • Providing no user or operator path to inspect and correct memory.

What I would put in production

  • Store provenance, timestamp and memory type with every durable memory.
  • Apply TTLs to time-sensitive facts.
  • Prefer current source-of-truth data over stale remembered conclusions.
  • Detect conflicts instead of silently picking one value.
  • Support correction, deletion and audit of important memories.

What I would monitor

memory age at use
memory/source conflicts
correction rate
tasks affected by stale memory
