≋ The model is fast, but the system is getting slower every minute

Agents can create work faster than downstream tools, queues or humans can safely consume it.

What it looks like

  • Queue depth grows even though individual model calls are healthy.
  • Background jobs start minutes or hours after users submit them.
  • Retries amplify an already overloaded dependency.

Why this happens

Agent systems are producers of downstream work. A fast planner can fan out dozens of API calls, sub-tasks or messages in seconds. If a database, queue consumer, vendor API or approval team is slower, work accumulates. Without backpressure, the agent keeps producing more requests and can turn a small slowdown into a system-wide incident.

A simple real-world example

A reconciliation agent discovers 8,000 mismatches and launches a repair task for each one. The downstream vendor API allows 100 writes per minute. Workers keep accepting tasks, retries start on 429 responses, and the queue grows faster than it drains. The model tier looks healthy while completion latency climbs from minutes to hours.

What teams usually get wrong

  • Scaling only the model workers.
  • Retrying rate-limit errors immediately.
  • Measuring request latency but not queue wait time.
  • Allowing one tenant or agent run to consume all worker capacity.

What I would put in production

  • Apply bounded queues and per-tenant concurrency limits.
  • Propagate downstream capacity signals back to planners.
  • Use exponential backoff with jitter for retryable pressure.
  • Prioritize or shed low-value work when capacity is exhausted.
  • Separate queue wait, execution time and model time in latency metrics.

What I would monitor

queue depth and age
arrival rate vs completion rate
429/overload retries
time spent waiting before execution
