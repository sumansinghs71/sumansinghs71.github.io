Production problem

∞ The agent is busy, but it is not making progress

A loop can look healthy—model calls succeed, tools return 200—while the task goes nowhere.

What it looks like

  • The same search or tool runs repeatedly.
  • Token cost rises while the user sees no new progress.
  • The agent keeps changing its plan but never reaches a verifiable outcome.

Why this happens

Most agent loops are built around activity: reason, call a tool, observe, repeat. Activity is not progress. If the system has no machine-checkable definition of progress or completion, the model can keep finding plausible next steps forever. Tool errors, weak search results, or conflicting context make this worse because every failure gives the model another reason to try something slightly different.

A simple real-world example

An incident agent is asked why checkout latency is high. It checks logs, then metrics, then logs again with a different query, then the same dashboard at a different time range. Every call succeeds. Twenty minutes later it has spent thousands of tokens but has not produced evidence strong enough to support or reject a hypothesis.

What teams usually get wrong

  • Using only a maximum-step limit. It stops cost, but it does not define success.
  • Letting the model decide 'I am done' with no external check.
  • Treating every new tool call as progress.
  • Retrying the same weak strategy without changing information or constraints.

What I would put in production

  • Define progress signals: new evidence, reduced candidate set, completed subtask, verified state change.
  • Track repeated tool+argument patterns and repeated hypotheses.
  • Use separate budgets for steps, time, tokens and expensive tools.
  • Add verifier checks for completion-critical tasks.
  • Escalate when the agent is active but progress has plateaued.

What I would monitor

steps per successful task
repeat-call ratio
time since last progress signal
cost per completed outcome
