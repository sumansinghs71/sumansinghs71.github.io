Model Control PlaneProduction failure pattern

404Config said the model existed. The provider said 404.

Your model catalog can stay green after the actual serving deployment has been removed, renamed or retired.

agent config→catalog: ACTIVE→provider→deployment: 404
Two control planes, two different realities.
Signals in production
  • A deterministic model-not-found error repeats across retries.
  • Internal config/database still marks the deployment active.
  • Restarts do nothing because the bad reference is durable.
Failure boundary

Internal control-plane truth diverges from provider serving-plane truth.

01

Why it happens

Model IDs are copied into catalogs, agent records, feature flags and deployment manifests. Provider inventory changes independently. Without reconciliation, stale references can outlive the resource they point to.

02

Production-shaped example

A dedicated deployment is removed during migration, but active agents still reference its old deployment key. Every call fails deterministically; retries only generate more identical 404s.

What fooled the team
retrying a deterministic not-foundvalidating only at agent creation timedeleting before proving zero live references
First 5 minutes
  1. Classify the error as deterministic, not transient.
  2. Compare the referenced deployment ID with live provider inventory.
  3. Stop retries, choose a validated target, then repair the durable reference.
03

Controls

Prevent the failure, detect it early, then recover without making it worse.

PREVENT
  • Run a reconciler between internal model catalog and provider inventory.
  • Block retirement while active references remain.
  • Preflight deployment existence during release and agent activation.
  • Use staged retirement: announce → migrate → drain → verify → remove.
DETECT
  • Alert separately on model/deployment-not-found.
  • Continuously report configured-vs-serving drift.
  • Track live consumers per model/deployment version.
RECOVER
  • Stop retrying the missing target.
  • Route to a pre-validated compatible target when policy permits.
  • Repair config and verify all consumers converge.
Prove it with failure injection
  • remove a referenced test deployment
  • rename/version a target
  • rollback model mapping
  • retirement with hidden live consumer
