Production problem

◌ Everything says SUCCESS, but the user still failed

Infrastructure can be green while the actual business outcome is wrong.

What it looks like

  • HTTP requests succeed and traces have no errors, but users repeat the task manually.
  • Agent completion rate is high while support complaints rise.
  • The final message sounds confident but the requested state change never happened.

Why this happens

Traditional monitoring answers operational questions: did the service respond, did the tool throw, did latency stay under the threshold? Agent systems need another layer: did the user's goal actually become true? The model can produce a polished final answer even when a tool returned partial data, an approval never completed, or the external state never changed.

A simple real-world example

A travel agent says, 'Your reservation has been updated.' The airline API returned 200 for the request, so every technical dashboard is green. But the response body says `status=pending_manual_review`. The agent treated transport success as task success and told the user the job was done.

What teams usually get wrong

  • Equating HTTP 200 with tool success.
  • Equating a model's 'done' message with workflow completion.
  • Measuring only latency, exceptions and token cost.
  • Using one global success metric for very different task types.

What I would put in production

  • Define a semantic success condition for each important task.
  • Validate postconditions against the source of truth.
  • Separate accepted, processing and completed states.
  • Sample completed runs for human or deterministic verification.
  • Turn silent failures into permanent regression cases.

What I would monitor

verified task success
user retry/reopen rate
postcondition mismatch rate
human disagreement with agent completion
