Safety & Security

🔑 The agent was healthy. Its credential was not.

Secret rotation is a security control, but stale credentials can turn it into a production outage.

What it looks like

  • Workers stay alive while every downstream call starts returning authentication errors.
  • Only long-running processes fail after a rotation.
  • Restarting the worker appears to fix the issue.

Why this happens

Agents often cache credentials longer than their validity. Rotation changes authority outside the process, so a runtime that never refreshes identity can remain healthy while its ability to act has expired.

A simple real-world example

A background agent starts a multi-hour task with a valid credential. The credential rotates while it is running. Later tool calls reuse the stale value and fail even though the worker, model and network are healthy.

What teams usually get wrong

  • Loading secrets only at process startup.
  • Using long-lived shared service credentials.
  • Retrying 401/403 responses without refreshing identity.
  • Restarting as the permanent credential-refresh mechanism.

What I would put in production

  • Prefer short-lived credentials and managed identity where possible.
  • Refresh credentials through a supported lifecycle, not ad-hoc caches.
  • Distinguish authentication failure from tool failure.
  • Revalidate authority when long-running work resumes.
  • Test rotation while work is actively running.

What I would monitor

credential refresh failures
401/403 rate by tool
credential age
re-authentication success
Takeaway: A running agent needs an identity lifecycle, not just a secret.
